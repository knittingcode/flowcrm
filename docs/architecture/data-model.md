# Data model: core schema

The foundation tables of FCRM-003 section F and backlog item FCRM-FND-007,
created by `backend/migrations/Version20261022000000.php`. Entities live in
the `Domain` layer of their module (`docs/architecture/backend-modules.md`).

## Conventions

| Topic | Convention |
|---|---|
| Identifiers | `uuid`, UUIDv7 generated by the application (`Symfony\Component\Uid\Uuid::v7()`) |
| Instants | `timestamptz` (DBAL `datetimetz_immutable`, second precision), stored in UTC |
| Tenant tables | `organization_id uuid NOT NULL` plus `UNIQUE (organization_id, id)`, so child tables can reference `(organization_id, id)` |
| References between modules | by ID only (no ORM associations); the foreign keys are declared by each module's `Infrastructure\Persistence\*Schema` listener so that `doctrine:schema:validate` compares them |
| Removal | rows are not deleted: memberships get `status = 'REMOVED'` and `removed_at`, stages `archived_at` |

## Tables

| Table | Module | Constraints in the database |
|---|---|---|
| `users` | Identity | `UNIQUE (lower(email))` (`users_email_lower_key`); `CHECK (length(email) <= 254)` |
| `organizations` | Organizations | `CHECK (currency IN ('EUR','PLN','USD','GBP','CHF','SEK','NOK','DKK','CZK'))`; the timezone is checked as an IANA identifier by the entity |
| `memberships` | Organizations | FK → `organizations`, FK → `users`; `UNIQUE (organization_id, user_id)`; `UNIQUE (organization_id, id)`; `CHECK (role IN ('ADMIN','MANAGER','REP'))`; `CHECK (status IN ('ACTIVE','REMOVED'))`; `CHECK ((status = 'REMOVED') = (removed_at IS NOT NULL))`; index `(user_id) WHERE status = 'ACTIVE'` |
| `pipelines` | Sales | FK → `organizations`; `UNIQUE (organization_id)` (one pipeline per organization); `UNIQUE (organization_id, id)` |
| `pipeline_stages` | Sales | composite FK `(organization_id, pipeline_id)` → `pipelines (organization_id, id)`; `UNIQUE (organization_id, id)`; active names unique per pipeline regardless of case (`pipeline_stages_active_name_key`, `WHERE archived_at IS NULL`); `UNIQUE (pipeline_id, position) DEFERRABLE INITIALLY DEFERRED` (stages can be reordered in one transaction) |
| `audit_events` | Audit | FK → `organizations` (nullable for platform events); `CHECK (actor_type IN ('user','platform_operator','system'))`; `changes jsonb`; `ip inet`; indexes `(organization_id, occurred_at DESC, id DESC)` and `(organization_id, entity_type, entity_id, occurred_at DESC)`; **append-only**: triggers reject `UPDATE`, `DELETE` and `TRUNCATE` for every role (SQLSTATE 42501) |

`schema_baseline` (FND-004) remains.

### Notes on the implementation

- `doctrine:schema:validate` (BE-07) compares tables, columns, foreign keys
  and indexes with the mapping. DBAL does not read CHECK constraints,
  triggers, deferrability or expression indexes; those are covered by the
  database tests below. The stage-name index is written with expression
  columns only (`(pipeline_id::text), lower(name)`), because DBAL would
  otherwise read it as a different index on `pipeline_id`.
- `inet` is mapped by the DBAL type `App\Shared\Infrastructure\Persistence\InetType`.
- The migration is additive. Its `down()` drops the tables (including audit
  rows) and is meant for development and the BE-08 round trip only.

## Tenancy and authorization boundary

These tables are the data foundation only. They do **not** isolate tenants
by themselves:

- The composite foreign keys guarantee that a stage cannot belong to another
  organization's pipeline, even if application code is wrong. Later tenant
  tables (accounts, contacts, opportunities, tasks) follow the same pattern.
- Tenant isolation of reads and writes comes from the request path: the
  tenant resolver (an `ACTIVE` membership for the current user), policies,
  and repositories that always filter by `organization_id` (FCRM-003 section
  G, FND-009). Row-Level Security is a later, separate decision (ADR-004,
  FND-016).
- Rules across rows, such as the last-admin rule (BR-03) and the stage
  reorder and archive rules (BR-15), belong to the use cases.
- Authentication, sessions and passwords are not implemented
  (`users.password_hash` is written by FND-008).
